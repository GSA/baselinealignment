# Accessibility development instructions

Use these instructions when creating or remediating web content or non-web documents. Apply the starter instructions and the appropriate development/creation skill as task guidance, either directly or through a supported tool. Read its bundled scope, full criterion reference, Baseline reference and document-format reference where applicable.

1. Establish all applicable WCAG 2.0, 2.1 and 2.2 A/AA criteria and the relevant Baseline procedures. Use the coverage inventory to retain missing-case and review gaps. Record non-web exceptions, no-test-required dispositions and supplemental checks distinctly.
2. Build a task-oriented artifact with native structure: headings/lists/tables, meaningful names and alternatives, reading/focus order, input labels/errors, usable controls and accessible media. Preserve intent and data semantics.
3. Apply newer contrast, responsive presentation, hover/focus, pointer, input, help and authentication guidance where applicable; label it supplemental rather than mapped to a Baseline. Use the exact criterion exceptions and format-appropriate interpretation.
4. Save an initial artifact and inspect the actual rendered/native delivery. Combine supported automated checks with human keyboard, visual comparison and applicable assistive technology. Do not fabricate capability-dependent checks.
5. Make the smallest effective remediation in a working copy, preserving formulas, links, text, interactions and security/redactions. Retest affected requirements and likely regressions in the same environment; record initial/final stages separately.
6. Verify exports and dependencies independently. Report actual outcomes, unresolved issues, coverage limitations and human-review status. Do not claim completed validation because every instruction or catalog entry exists.
