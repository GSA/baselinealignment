# Generate, test and remediate

1. Identify web/non-web context, covered electronic content, intended tasks, native/export formats and delivery environments. Read and apply starter/development instructions and the appropriate creation/development skill with its references; supply them as task context when using a tool.
2. Plan all applicable incorporated WCAG 2.0 checks, Baseline procedures, conformance requirements and supplemental WCAG 2.1/2.2 checks. Record document exceptions and Parsing's no-test-required disposition; retain validation gaps independently.
3. Generate with native semantic structures, meaningful alternatives, correct reading/focus relationships, accessible input/media and appropriate presentation. Preserve formulas, links, controls and sensitive-content handling. Save initial revisions and dependencies.
4. Run relevant automated/checker tools and guided human testing on actual rendered/native content. Inspect every delivered export independently. Capture evidence and gaps instead of predicting passes from source code.
5. Remediate a working copy using the criterion and Baseline references; never alter original fixtures or evaluator answers. Recheck affected criteria and likely regressions, including complete user processes and delivery dependencies.
6. Record initial, remediated and generated stages separately. Report Baseline/Section 508 results separately from supplemental results, along with available-case evaluation coverage, remaining failures/gaps and human-review status.
7. When new or corrected Framework cases become available, pin a new suite revision and rerun the affected evaluations. Preserve earlier scoped results without extending them to untested cases or environments.
