# Word authoring and testing

Use this reference with the full criterion and Document Baseline references. Identify the actual Word version, OS, reading mode and assistive technology; also evaluate the delivered PDF or other export independently.

## Create or remediate

- Set a meaningful title and primary language; mark language changes through native text properties where supported.
- Use native heading styles with a coherent hierarchy, real lists and meaningful link text. Avoid spacing or text boxes as substitutes for structure.
- Keep meaningful objects in a usable reading sequence; use appropriate anchors/inline positioning. Check navigation through floating objects and multi-column content.
- Give meaningful images/charts equivalent alternatives and mark only true decoration as decorative. Supply detailed data or a narrative for complex graphics.
- Use native data tables with clear header relationships. Prefer simpler structures where they convey the same relationships. Do not impose a blanket ban on merged cells or demand filler text in every blank cell; repair actual ambiguity or lost associations and test complex structures.
- Label content controls and forms, convey required fields/instructions visibly, and preserve keyboard operation and meaningful tab order.
- Use adequate text and meaningful graphical contrast, non-color cues, usable text resizing and supported supplemental reflow/spacing. Do not use screenshots as the sole representation of text.
- Make embedded or linked media accessible, including captions, description, transcripts and usable playback controls as applicable. Preserve accessible content when protecting or restricting editing.

## Evaluate

Run the available native checker and inspect its unresolved warnings; do not stop at a clean report. Inspect navigation structure and table semantics, then read representative complex content with assistive technology and compare it with the visual content. Exercise links, forms, embedded media, keyboard focus and complete processes. Inspect headers, footers, footnotes and text boxes for meaningful information missing from ordinary reading. Test supplemental criteria with format-appropriate methods and document reader limitations.

Export with accessibility structure enabled using a supported path; reopen the actual export and inspect its structure, order, alternatives, links and language. Printing to a PDF driver is not an assurance that structure survives. Record checker, manual and export observations separately.

Source: [Section508.gov accessible documents](https://www.section508.gov/create/documents/). Follow the current format guide for UI-specific procedures rather than guessing menu locations.
