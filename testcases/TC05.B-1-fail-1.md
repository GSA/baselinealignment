title: User Controls - notification provided for change in content, but the role of the changed content is not accurate after the change

standard: WCAG
standard-ref: 4.1.2
standard-ref-url: https://www.w3.org/WAI/WCAG22/Understanding/name-role-value
descr: |
  When content changes reveal or update user controls, the role of the changed control must be accurate after the change. Specifically, selecting a feeling reveals a follow-up response control implemented as a contenteditable div with aria-label="Because...", but the editable control is not explicitly identified with an appropriate textbox role.

  The code sample includes changed content with an editable user control whose role is not accurately identified after the change. A successful test should identify a failure against Baseline 5.B Control Role.
result: Fail

| Test Instruction | Instruction Detail | Expected Test Case Result |
|------------------|--------------------|---------------------------|
| **IC-5.B** | Identify user controls for a distinct function that have an explicit role attribute (role="[value]"). Examples include forms, links, and toggle controls. |  |
| **5.B-1** | Check that the role of the user control is valid and appropriate for its function. [SC 4.1.2] * Only the roles listed in [Accessible Rich Internet Applications (WAI-ARIA) Section 5.3.2 Widget Roles](https://www.w3.org/TR/wai-aria/#attrs_widgets) are valid for user controls. |  |
| **Result** | If any of the above checks fail, then Baseline Test 5.B-ControlRole fails. |  |
