descr: |
  The focus order of keyboard-accessible interface components must preserve the meaning and usability of the page. Specifically, the Shipping Address and Payment Information form fields appear in a logical order and do not use tabindex values or scripting that changes the expected keyboard focus order.

  The code sample includes keyboard-accessible form fields with a focus order that preserves the meaning and usability of the page. A successful test should identify a pass against Baseline 2.B Focus Order.

|------------------|--------------------|---------------------------|
| **IC-2.B** | Keyboard accessible interface components (links, form fields, drop down menus, show/hide content, tree views, pop ups/light boxes, frames, iframes, etc.) that have a meaningful sequence of navigation. |  |
| **2.B-1** | Use the keyboard to navigate through interface components. |  |
| **2.B-1.a** | Use the keyboard to activate trigger controls that reveal hidden content (menus, dialogs, expandable tree list, etc.). |  |
| **2.B-1.a.i** | Check that the revealed focusable content is included in the focus order. [SC 2.4.3] |  |
| **2.B-1.a.ii** | Advance the focus through the revealed content. |  |
| **2.B-1.b** | Use the keyboard to close/hide the revealed content. |  |
| **2.B-1.b.i** | Check that focus is returned to the trigger control. (It is acceptable to Shift+ TAB once or use an arrow key to move the focus backward to the trigger control. [SC 2.4.3] |  |
| **2.B-2** | Check that the focus order preserves the meaning and usability of the page. [SC 2.4.3] |  |
| **Result** | If any of the above checks fail, then Baseline Test 2.B-FocusOrder fails. |  |
